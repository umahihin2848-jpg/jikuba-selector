# vNext Validation 12 — 相手の広がり / 絞り判断

Date: 2026-10-28
Status: Shadow only
Production change: none

## 目的

相手候補を単に5頭並べるのではなく、

- 本線相手
- 有力相手
- 押さえ
- 人気次点
- 穴注目

に分けたうえで、「本線を厚くしやすいレース」か「相手を広めに見たいレース」かを分かりやすく表示できるか確認する。

## 相手候補の役割

市場上位4頭の中で、基礎能力順位と終盤予測順位を使って固定分類する。

- 本線相手: 基礎能力4位以内 かつ 終盤予測4位以内
- 有力相手: どちらか一方が4位以内
- 押さえ: どちらも4位外

市場上位4頭の外は別表示する。

- 人気次点: 上位4頭の次に単勝市場で支持される馬
- 穴注目: 上位4頭の外で、基礎能力順位 + 終盤予測順位が最小の馬

穴注目は自動で買い目に追加しない。

## 役割の確認

2024–26、軸が3着内に来たレースで、各候補馬自身が3着内に来た率:

- 本線相手 41.4%
- 有力相手 28.5%
- 押さえ 23.3%

馬連用の2着内率:

- 本線相手 30.8%
- 有力相手 18.8%
- 押さえ 8.6%

本線相手は押さえより明確に高い。2024–26のwideで本線−押さえ差はrace-bootstrapでも正方向。

## 「構造拾い」の名称修正

旧qScoreによる5頭目は市場人気との結びつきが強く、純粋な能力・展開起点の穴馬ではない。

そのため「構造拾い」という表示はやめ、意味に合わせて「人気次点」とする。

Ability + M3のみで上位4人気外から選ぶ穴注目は、2024–26では追加価値が見えたが2020–23では安定しなかったため、研究表示に限定する。

## 相手の広がり

人気の散らばりには、単勝オッズを逆数化してレース内で正規化した市場シェアを使う。

`Neff ratio = (1 / sum(share^2)) / field`

区切りは2020–23の中央値を先に固定:

- cut = 0.48366774242113353
- cut以下: 人気が上位に集まる
- cut超: 人気がばらける

相手候補は、本線相手 → 有力相手 → 押さえ、同役割では市場順位の順に見る。

### 2020–23

軸が3着内に来た73レース:

- 人気集中 41 races: 上位2頭で相手捕捉 73.2%, 上位4頭 90.2%
- 人気分散 32 races: 上位2頭 68.8%, 上位4頭 87.5%

差は小さい。

### 2024–26

軸が3着内に来た91レース:

- 人気集中 56 races: 上位2頭で相手捕捉 76.8%, 上位4頭 89.3%
- 人気分散 35 races: 上位2頭 54.3%, 上位4頭 80.0%

上位2頭捕捉差は +22.5pt。race-bootstrap 95%CI は概ね +2.8pt 〜 +42.5pt。

ただし開発期では差が小さかったため、これを理由に自動で2頭へ絞らない。

## Shadow表示ルール

- vNext Axis A/B かつ 人気集中: `本線を厚くしやすい`
- 人気分散: `相手は広めに見たい`
- Axis C/D かつ 人気集中: `相手より軸を慎重に`
- その他: `相手の優先順位は普通`

この表示は購入点数を自動変更しない。

## 実装

- `vnext-opponent-diagnostic-shadow-v1.js`
  - vNext Axisを基準に相手候補を除外・分類
  - 本線相手 / 有力相手 / 押さえ / 人気次点 / 穴注目
- `vnext-race-breadth-shadow-v1.js`
  - 軸のTier、人気の散らばり、データ完全性を分解表示
  - `本線を厚くしやすい / 相手は広めに見たい / 相手より軸を慎重に`
  - Production買い目変更なし

## 禁止事項

- 2024–26の結果を見てNeff cutを再最適化しない
- `人気集中`だけを理由に2頭へ自動削減しない
- `穴注目`を自動6頭目として追加しない
- 本線相手の数が少ないことだけで購入点数を減らさない

2027 Forwardで、固定ルールのまま相手捕捉率と回収面を記録する。

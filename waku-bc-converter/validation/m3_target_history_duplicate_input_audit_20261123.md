# TARGET過去走の重複によるM3入力不整合・読取監査（2026-11-23）

## 目的と対象
ユーザー指定の位置取り研究を、本番M3と同一の入力で検証する前提として、TARGET `umadete.csv` の履歴行と公開アプリのパーサーを監査した。対象はJRA平地3勝／OP／L／G1〜G3・12〜18頭、2025年158R/2,372頭、2026年120R/1,798頭、合計**278R/4,170頭**。過去履歴は各レースの日付より前のみを使用。対象は過去走が全頭照合された特定コホートである。

## 最重要発見：同じレースの重複を「直近5走」として扱う
- 元TARGET CSVの総439,416行のうち、この研究対象の馬に該当276,465行。対象馬の馬名+18桁レースIDでのユニークキーは34,415件、重複行242,050件（除外前）。これは**今回の特定CSVの性質**であり、すべてのTARGETエクスポートが必ず重複するという主張ではない。
- 公式ソース `target-csv-compat-v1.js` はTARGETの `レースPCI→RPCI`、`通過1〜4→1角〜4角`、日付を補完する。**見出しの不一致だけでM3のデータが欠落するという前段の疑いは撤回**。
- `validated-queue-model-v1.js` の `hist()` と `finish600-simulator-v2.js` の `hist()` は`date<raceDate`の履歴の**直近5行**を取得し、18桁レースIDによる重複除去は行っていない。`ShapeCore.buildHistories`/`summarize`も同じ馬の同一レースIDを自動で1件に集約しない。
- TARGET互換変換に合わせ、障害・中止・取消等の行をフィルタしたオフライン監査では、対象**4,170頭中4,109頭（98.54%）**で直近5行に重複あり。直近5行のユニーク過去レース数は平均**1.60レース**。**1,995頭**は直近5行が実質1レースだけだった。

## 同じ公開M3係数による感度分析（完全なブラウザ再演ではない）
比較したもの：
- A「現行読取相当」：上記CSVのレース日より前の直近5**行**（重複保持）から、公開`remaining600_position.deployable_model`の数式、`finish600_model_v1.json`のM3固定19係数を計算。
- B「レースIDで重複除去」：同CSVのレース日より前の直近5**異なるレースID**を使用。固定係数は変更しない。

| 評価（2025+2026／278R・4,170頭） | 直近5行 | 過去5レース |
|---|---:|---:|
| 実測残600m先頭差とのMAE | 0.39858秒 | **0.37957秒** |
| M3近似上位3頭の3着内件数（834枠） | **266頭** | 251頭 |

- 同じ馬の残600m予測値の絶対差平均**0.157秒**、M3コア近似スコア差平均**0.178秒**、馬のM3近似順位が変わった割合**88.5%**。**278R中272R**で上位3頭の構成が変わった。
- 2026年だけでは残600m MAE 0.38227→**0.36585秒**（旧−新+0.01641秒、レース単位ブート95%CI **+0.00837〜+0.02459秒**）、M3近似上位3頭の3着内件数**112/360→105/360**。つまり重複除去は位置差MAEを改善したが、近似M3の3着内数を改善したわけではない。
- 2025年では600m MAE 0.41094→0.38996秒、近似上位3頭の3着内154/474→146/474。
- **これは本番アプリの完全リプレイではない**。Core/ValidatedQueue/Remaining600の各入力を公開係数から読み取り再実装した感度分析であり、ブラウザで使用する `ShapeCore` 入力の細部、確定馬番とCSV仮番号、ライブ各addonの更新順序・公式軸判定まで完全一致させていない。過去年度は他の研究で参照済みのため、真の未知年テストでもない。
- 上位3頭好走数はレース単位の時系列／オッズまで評価した勝率ではない。低いMAEが必ず高い回収率になるわけではない。

## アプリの研究診断追加（本番ロジック非変更）
- `finish600-simulator-v2.js` の過去履歴レコードに`raceId`を保存し、直近5行のユニークレース数`hist_unique_races5`と重複数`hist_duplicate_rows5`を計算して参考メタデータとしてのみ出力。
- `race-position-competition-v1.js` の研究パネルに馬別「直近履歴：○レース／○行（重複あり）」と、該当馬頭数の警告を追加。研究用順位分布のJSONにも`historyDistinctRacesLast5`、`historyDuplicateRowsLast5`を保存。レースIDが無ければ判定不可を明示。
- `finish600_model_v1.json`の係数、既存M3機能の特徴量リスト、公式Ability C/v1、P10、軸・相手、BUY/PASS、馬券ロジックは**変更しない**。
- GitHubへの反映、JavaScript構文・研究パネルの警告表示・JSON保存・仮想順位の非変更は模擬ブラウザで確認。GitHub Pages配信およびiPhone Safariでの実機E2Eは未確認。
- 注意：これまで表示していた「過去位置SD」は「過去5レース」ではなく**重複を含み得る過去最大5行の標準偏差**。ユーザーCSVに重複があると過小評価されることがある。研究表示では行数表記に変更した。

## 今後の採用判断
1. 同じ過去レースIDを複数行含む入力を検知。重複除去後の履歴／日付・レースID・全頭整合をブラウザの固定入力で比較する**別のシャドーパス**を作る。本番計算を直接置き換えない。
2. `ShapeCore`→`ValidatedQueueState`→`Remaining600ValidatedState`→`Finish600State`→本番M3／公式軸まで、実際のブラウザ入出力スナップショットを保存してPythonリプレイと対比する。
3. 未使用の将来レースで、発走前に本番・重複除去シャドーの600m先頭差、順位分布、M3上位、3着内確率と締切前オッズを固定し、結果まで追跡する。
4. 位置差MAEだけでなくM3予測Brier、Top3上位捕捉、実購入可能な価格でのROIが安定的に改善するまで本番置換不可。障害・取消等の除外ルールを両パスで一致させる。
